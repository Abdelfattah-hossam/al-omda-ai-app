# Performance phase2: search and assets

Global search now sends one250ms-debounced GET to an authenticated,no-store endpoint. An invoker/RLS-scoped SQL function searches each caller's project titles,requests,step headings,expected outputs,and saved result text. It returns at most12project/output hits and12file metadata hits,never result bodies. File metadata comes from all caller-owned workspace folders in one query instead of one Storage list for each project. SQL uses literal substring matching,so `%` and `_` are not wildcard expansions. Existing navigation search and signed-out local project search remain. Failed searches show a retry action instead of a false empty result. Closing,account changes,and typing abort stale requests.

The assets screen renders its first100files immediately. More files remain available through Load more files. Folder changes discard stale page replies;duplicates across boundaries are merged by path. Upload,preview,download,delete confirmation,and general/project folder selection remain unchanged. The existing bounded array API stays compatible with other callers.

Database rollback fixture matched text found only in saved output,returned the output heading without its body,treated `%` literally,and confirmed anonymous RPC denial. An unrelated authenticated account got empty projects and assets. Synthetic mobile UI displayed100files without reading page2,then loaded file101on demand. It found output/file hits without any project folder scan. Error/next-query recovery and cancelled responses were checked. Screenshots were visually inspected at390px. No physical iPhone or1000-concurrent acceptance test was performed.

This removes network N+1 and unbounded client payloads. It does not claim constant-time full-text search at arbitrary project counts: literal substring matching still scans caller-owned text under RLS. Search results remain capped to12per category,as before. Empty search results are now ordered by created timestamp and ID/name for deterministic recent hits.
