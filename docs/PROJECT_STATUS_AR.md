# حالة مشروع AL OMDA AI وخطة استكماله

> آخر تحديث: 13 نوفمبر 2026  
> هذا الملف يوثق ما يظهر في المستودع وسجل التغييرات المتاح. وجود كود أو نجاح CI لا يعني وحده أن الميزة اختُبرت على جهاز حقيقي أو نُشرت في الإنتاج.

## الملخص التنفيذي

المشروع تجاوز مرحلة واجهة الدردشة فقط، وأصبح يحتوي على أساس لتطبيق مساحة عمل عربية مع Runtime محلي للأدوات والوكلاء. لكنه ما زال في مرحلة التطوير التجريبي، ولم يثبت بعد أنه وكيل مستقل متكامل وآمن لكل أنواع المهام.

## ما تم بناؤه أو إضافته

### تطبيق الويب ومساحة العمل
- واجهة React/Vite عربية وإنجليزية.
- تسجيل دخول وجلسات مصادقة عبر Supabase.
- بيانات المستخدم والمهام والمحادثات والذاكرة الخاصة مع سياسات RLS.
- دردشة AI مع توجيه إلى مزودي Gemini وOpenRouter عند ضبط الإعدادات والمفاتيح.
- خطط مشاريع بخطوات قابلة للموافقة والإيقاف والاستئناف.
- حدود استخدام يومية عبر Supabase RPC.
- مساحة مستخدم وتفضيلات ورفع صورة الحساب.
- مسارات تصدير مستندات وجداول بيانات، مع بدائل عند تعذر التصدير.
- هيكل تطبيق ويب قابل للتثبيت.

### Agent Runtime المحلي – تجريبي
- أدوات استعراض وقراءة وكتابة الملفات داخل مساحة العمل مع فحوصات للمسارات والروابط الرمزية.
- حلقة تنفيذ تعتمد على النموذج لاكتشاف الأدوات واستدعائها.
- جلسات محفوظة واستعادة الجلسات.
- بوابات موافقة قبل عمليات كتابة الملفات وبعض أوامر الطرفية وأدوات MCP.
- اكتشاف Skills من مجلد المشروع.
- دعم MCP عبر stdio مع موافقة المستخدم على الاستدعاءات.
- تكامل Playwright MCP وإعداد متصفحات Chromium وFirefox وWebKit.
- Browser Workspace مع قائمة سماح لأسماء المضيفين.
- خدمة اختيارية لتشغيل Runtime محليًا عند بدء الجهاز.
- تكامل اختياري للتحكم المكتبي عبر MCP، ويتطلب تثبيتًا محليًا وصلاحيات واضحة.
- أدوات HTTPFlow للمقارنة بين الاستجابات وحفظ سجل منقح وتصديره.
- أدوات Web Recon سلبية لفحص DNS وشهادة TLS وترويسات الأمان وrobots.txt.
- مساعدات تحليل CTF محلية، مع توضيح أن بعض النتائج استدلالية وليست إثباتًا.
- دعم نقاط اتصال نماذج محلية متوافقة مع OpenAI مثل LM Studio، مع خيار endpoint احتياطي.
- تنفيذ أوامر الطرفية معطّل افتراضيًا.

### الأمان والبنية
- سياسات CORS محددة واختبارات لها.
- حماية مسارات ومساحات العمل من اجتياز المسارات وبعض هجمات الروابط الرمزية.
- حماية ملفات بيانات الاعتماد من وصول الوكلاء المتخصصين المفوضين.
- مساحة مقترحات معزولة للوكلاء بدل تعديل ملفات المشروع مباشرة.
- أساس لمشرف Agent Supervisor يتحقق من تحديثات Git قبل تطبيقها.
- فحوصات TypeScript والاختبارات والبناء ضمن GitHub Actions.

## ما لم نثبت اكتماله بعد

هذه النقاط لا ينبغي وصفها بأنها منجزة قبل تنفيذها واختبارها:

1. عزل تنفيذ الوكيل داخل Sandbox قوي (مثل حاويات مع حدود CPU والذاكرة والوقت والشبكة والملفات).
2. إكمال واختبار تحويل النماذج تلقائيًا عند timeout أو أخطاء المزود أو نفاد الحصة، مع cooldown وقيود إعادة المحاولة وعدم كشف المفاتيح في السجلات.
3. إكمال دورة تعاون الوكلاء: تخطيط، توزيع، تنفيذ، مراجعة، تجميع النتائج، وموافقات للعمليات الحساسة.
4. اختبارات تكامل فعلية للمتصفح وتنفيذ الأدوات والملفات، لا اختبارات وحدات فقط.
5. التحقق من أن كل أداة لا تتجاوز صلاحيات المستخدم أو نطاق المواقع والملفات المصرح بها.
6. إعداد توقيع وتوثيق تطبيق سطح المكتب حسب أنظمة التشغيل والشهادات المتاحة؛ لا يجوز اعتبار التوقيع مكتملًا دون شهادات صالحة.
7. اختبار تطبيق سطح المكتب على أجهزة فعلية بأنظمة Windows وmacOS وLinux.
8. التحقق من نشر Cloudflare Worker وصحة النسخة الإنتاجية بعد كل دمج؛ لا يوجد في هذا التقرير إثبات مستقل بأن آخر تغييرات PR #20 نُشرت للإنتاج.
9. اختبار تدفق الملفات من الطلب حتى المعاينة والتنزيل على الهاتف والكمبيوتر، واختبار مزامنة الجلسات والمهام.
10. مراجعة نهائية للأمان والخصوصية والأسرار والصلاحيات والتعامل مع فشل الخدمات.

## ترتيب التنفيذ المقترح

1. إغلاق مراجعة PR #20 ومعالجة أي ملاحظات حقيقية، ثم دمجه بعد اكتمال المراجعة المطلوبة.
2. بناء Sandbox للتنفيذ المحلي واختبار منع الوصول خارج مساحة العمل.
3. إكمال Provider failover واختبار الأعطال والحصص والمهل الزمنية.
4. استكمال Supervisor وتنسيق الوكلاء والموافقات وسجل تنفيذ يمكن مراجعته.
5. إضافة اختبارات تكامل للمتصفح والملفات والطرفية وMCP.
6. استكمال حزمة سطح المكتب والتوقيع حيث تتوفر الشهادات.
7. تنفيذ اختبارات قبول على الهاتف والكمبيوتر، ثم التحقق من النشر والإنتاج.
8. إصدار تقرير إطلاق يوضح ما اجتاز الاختبارات وما بقي مقيدًا أو تجريبيًا.

## حدود مهمة

- لا يتم تشغيل أوامر طرفية خطرة أو عمليات على الجهاز دون موافقات وصلاحيات محددة.
- Runtime المحلي ليس هو Cloudflare Worker؛ التحكم في جهاز المستخدم يحتاج تثبيت Runtime أو تطبيق مرافق على الجهاز.
- وجود تكامل متصفح أو MCP لا يعني أن هناك Sandbox شبكيًا كاملًا.
- نجاح CI لا يعادل اختبارًا فعليًا على كل نظام تشغيل.
- لا تُدرج مفاتيح API أو كلمات مرور أو بيانات اعتماد في هذا الملف.
