# حالة مشروع AL OMDA AI وخطة استكماله

> آخر مراجعة: 13 نوفمبر 2026  
> هذا التقرير يفرق بين الكود المدمج، واختبارات CI، والاختبارات العملية على أجهزة المستخدمين. وجود ميزة في الكود لا يعني وحده أنها اجتازت اختبار قبول أو نُشرت في الإنتاج.

## الملخص التنفيذي

المشروع يحتوي على تطبيق ويب عربي/إنجليزي، ومحادثة AI، وبيانات مستخدم ومهام ومحادثات وذاكرة على Supabase، إضافة إلى Runtime محلي تجريبي لأدوات الوكيل وMCP والوكلاء المتخصصين. ما زال المشروع في مرحلة التطوير والقبول، ولا ينبغي وصفه بأنه وكيل مستقل متكامل أو جاهز للإطلاق قبل استكمال اختبارات الهاتف والكمبيوتر والإنتاج.

## ما تم دمجه على main

### التطبيق والبيانات
- واجهة React/Vite عربية وإنجليزية ومساحات للمحادثة والمهام والوكلاء وسجل المحادثات والملف الشخصي.
- تسجيل الدخول والجلسات باستخدام Supabase Auth.
- جداول المستخدمين والمهام والمحادثات والذاكرة الخاصة مع RLS.
- محادثة AI مع توجيه إلى Gemini وOpenRouter بحسب الإعدادات والمفاتيح المتاحة.
- خطط مهام بخطوات وموافقات، وحدود استخدام يومية عبر Supabase RPC.
- أساس لتصدير مستندات Word وجداول Excel وتطبيقات HTML، مع تحقق بنيوي لبعض المخرجات.
- صفحة حالة المشروع داخل التطبيق أضيفت عبر PR #27.

### استقرار الشات
- PR #38 دمج إصلاحات لتقليل اهتزاز التمرير أثناء تدفق الردود، مع الحفاظ على سلوك التمرير الذي يتحكم فيه المستخدم.
- PR #39 يحتوي إصلاحًا واختبارات لعزل نية الطلب الحالي عن الطلبات السابقة، بحيث لا تتحول التحية إلى طلب Word/Excel بسبب رسالة قديمة. CI نجح، لكن PR ما زال مفتوحًا ولم يدمج بعد؛ مراجعة Robin أعادت HTTP 429 بسبب حد مزود النموذج، وتجري إعادة المحاولة.
- PR #40 يعيد إصلاح تخطيط صفحة الشات فوق آخر main دون تعديل منطق التمرير أو مكونات الشات. CI ومراجعة Robin قيد التشغيل عند آخر مراجعة؛ Gemini PR Review فشل بسبب مزود المراجعة.

### Agent Runtime المحلي – تجريبي
- أدوات قراءة وكتابة الملفات داخل مساحة العمل مع فحوصات للمسارات والروابط الرمزية.
- حلقة تنفيذ تعتمد على النموذج لاكتشاف الأدوات واستدعائها، مع حفظ الجلسات واستعادتها.
- موافقات قبل كتابة الملفات وأوامر الطرفية واستدعاءات MCP وبعض طلبات HTTP الموثقة.
- اكتشاف Skills وMCP عبر stdio، مع تكامل إعداد Playwright MCP.
- Browser Workspace بقائمة سماح لأسماء المضيفين.
- تكامل اختياري للتحكم المكتبي عبر MCP، ويتطلب تثبيتًا محليًا وصلاحيات نظام التشغيل.
- HTTPFlow لمقارنة استجابات أدوار مصرح بها وتسجيل ملخصات منقحة.
- أدوات Recon سلبية لفحص DNS وشهادات TLS وترويسات HTTP وrobots.txt.
- مساعدات CTF محلية لتحليل النصوص والرموز، وليست أدوات استغلال أو كسر كلمات مرور.
- دعم مزودي نماذج محلية/بعيدة متوافقة مع OpenAI، مع توجيه حسب الغرض وخيار fallback وcooldown.
- مشرف محلي لإعادة تشغيل Runtime وتحديث checkout بشروط تحقق؛ التحديث التلقائي معطل افتراضيًا.
- PR #37 أضاف تنفيذًا اختياريًا لأوامر الطرفية داخل Docker. الوضع الافتراضي ما زال معطلًا، وكل أمر يحتاج موافقة صريحة.

### الأمان وSupabase
- سياسات CORS واختبارات لها.
- فحوصات لنطاقات ومسارات مساحة العمل.
- عزل مقترحات الوكلاء المتخصصين في مجلدات منفصلة بدل تعديل المشروع مباشرة.
- RLS مفعّل على جداول التطبيق.
- طُبقت على مشروع Supabase الفعلي migrations لتقييد تنفيذ دوال SECURITY DEFINER، ومنع anon من صلاحيات الجداول، وتطبيق أقل صلاحيات لازمة لدور authenticated.
- اختبارات قاعدة البيانات السابقة أثبتت أن anon لا يستطيع قراءة الجداول، وأن مستخدمًا لا يرى صفوف مستخدم آخر، وأن استدعاء دالة الاستخدام يعمل ضمن جلسة authenticated. هذه اختبارات قاعدة بيانات، وليست اختبارًا كاملًا من واجهة التطبيق.

## ما لم يثبت اكتماله بعد

1. اختبار قبول حقيقي من واجهة التطبيق بعد تسجيل دخول المستخدم: إنشاء مهمة، حفظ محادثة، استعادة محادثة، قراءة/كتابة الذاكرة، وإكمال المهمة.
2. اختبار إنشاء Word وExcel وHTML على ملفات حقيقية، والتحقق من الفتح والمعاينة والتنزيل على الهاتف والكمبيوتر.
3. اختبار مزامنة الجلسات والمهام والملفات بين الهاتف والكمبيوتر دون تحديث يدوي.
4. اختبار محادثة صوتية ثنائية الاتجاه؛ لا يكفي اختبار تحويل الكلام إلى نص فقط.
5. اختبارات شاملة لتحويل مزودي AI عند 429 و503 والمهلة وانقطاع الشبكة، مع التأكد من عدم تكرار الخصم أو كشف المفاتيح.
6. اختبار Runtime محليًا على أجهزة فعلية، بما في ذلك الموافقات ورفض الأوامر والوصول خارج مساحة العمل.
7. اختبار Docker على نظام مدعوم. الحاوية تشارك نواة نظام المضيف، لذلك ليست ضمان عزل مطلقًا.
8. اختبار Playwright وMCP وComputer Use على أجهزة فعلية. Runtime المحلي على الكمبيوتر لا يمنح الهاتف تلقائيًا تحكمًا عن بعد؛ يلزم اتصال مرافق آمن ومشفّر لذلك.
9. مراجعة نهائية لصلاحيات Supabase. أربع دوال SECURITY DEFINER متاحة لدور authenticated لأنها مطلوبة للتطبيق وتتحقق من auth.uid؛ يجب استمرار اختبارات الوصول. حماية كلمات المرور المسرّبة في Supabase Auth غير مفعلة. كما أن default privileges لدور supabase_admin ما زالت أوسع من المطلوب ولم نتمكن من تعديلها.
10. اختبار نشر Cloudflare Worker والتأكد من أن نسخة الإنتاج تطابق commit المقصود. نجاح Preview أو CI لا يثبت نشر الإنتاج.
11. تجهيز المستودع للنشر العام: آخر فحص أظهر أن GitHub repository ما زال Private. لم تتوفر في أدوات GitHub المتصلة صلاحية/عملية لتغيير visibility، لذلك لم يتم تحويله إلى Public. الترخيص MIT وحده لا يجعل المستودع عامًا.

## ترتيب التنفيذ المقترح

1. إكمال CI والمراجعة لـPR #39 وPR #40، ومعالجة الملاحظات قبل الدمج.
2. تحديث هذا التقرير والتوثيق عند كل مرحلة دمج.
3. تنفيذ اختبارات قبول الواجهة وقاعدة البيانات من جلسة المستخدم الفعلية.
4. اختبار Word وExcel والصوت والمزامنة على الهاتف والكمبيوتر.
5. استكمال اختبارات failover ومراقبة أخطاء مزودي النماذج.
6. اختبار Runtime وDocker وMCP والمتصفح والتحكم المكتبي على أجهزة فعلية.
7. معالجة ملاحظات أمان Supabase المتبقية.
8. التحقق من نشر Cloudflare للإنتاج بعد كل دمج.
9. تحويل المستودع إلى Public من إعدادات GitHub بعد إتاحة صلاحية إدارة المستودع، ثم التحقق من ظهوره العام.

## حدود مهمة

- تنفيذ الطرفية معطل افتراضيًا. وضع host غير معزول ويستخدم صلاحيات حساب نظام التشغيل.
- Docker يقلل نطاق الوصول لكنه يشارك نواة المضيف ولا يحمي من كل ثغرات النواة أو محرك الحاويات.
- Runtime المحلي ليس هو Cloudflare Worker؛ التحكم في جهاز المستخدم يحتاج Runtime على ذلك الجهاز أو اتصالًا بعيدًا آمنًا منفصلًا.
- وجود تكامل متصفح أو MCP لا يعني وجود Sandbox شبكي كامل.
- نجاح CI لا يعادل اختبارًا فعليًا على كل نظام تشغيل أو تحققًا من الإنتاج.
- لا تُدرج مفاتيح API أو كلمات مرور أو بيانات اعتماد في هذا الملف.
