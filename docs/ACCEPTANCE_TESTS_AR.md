# اختبارات القبول الإلزامية — العمدة AI

هذه القائمة مرجع تنفيذ واختبار، وليست ادعاءً بأن الاختبارات نجحت. لا يُغلق أي بند إلا بدليل تشغيل فعلي.

## 1. الموافقة والتنفيذ — أعلى أولوية

- [ ] تحميل مشروع محفوظ بحالة مراجعة مع جميع المراحل.
- [ ] الضغط على «موافقة» يرسل الطلب الصحيح إلى API، ويظهر تحميل/تعطيل لمنع النقر المكرر.
- [ ] بعد نجاح API تتغير حالة المرحلة في الواجهة وتُحفظ في قاعدة البيانات.
- [ ] الموافقة وحدها لا تستدعي نموذج AI ولا تنفذ المرحلة؛ لا يبدأ التنفيذ إلا بعد الضغط الصريح على «تنفيذ الخطوة».
- [ ] بعد فشل API تبقى الحالة السابقة، وتظهر رسالة عربية توضح الخطأ، مع إمكانية إعادة المحاولة.
- [ ] الضغط على «تنفيذ» يشغّل المرحلة المعتمدة فقط، ثم يحفظ الناتج ووقت التنفيذ وحالته.
- [ ] لا تبدأ المرحلة التالية قبل نجاح المرحلة السابقة وحفظ ناتج غير فارغ.
- [ ] رفض المرحلة يعيدها للمراجعة ولا يسمح بتجاوز التسلسل.
- [ ] الإيقاف/الإلغاء يوقف التنفيذ بأمان، والاستئناف يكمل من checkpoint دون إعادة مرحلة ناجحة.
- [ ] أثناء تشغيل المشروع تظهر حالة تشغيل واضحة، وتُعطّل الأزرار المتعارضة مثل اعتماد/رفض/تعديل/تعليق/إيقاف مؤقت حتى لا تتداخل العمليات.
- [ ] النقر المزدوج أو إعادة إرسال الطلب لا يكرر التنفيذ أو إنشاء المخرجات.
- [ ] تحديث الصفحة أو إعادة فتح الحساب يعرض الحالة المحفوظة من الخادم.
- [ ] موافقة معلقة ونتيجة تنفيذ تتزامنان بين جهازين للحساب نفسه.
- [ ] كل زر ظاهر إما ينفذ فعلًا أو يكون معطلًا مع سبب واضح؛ لا أزرار شكلية.

## 2. اختبارات فشل سابقة يجب إعادتها

### Word
- [ ] طلب إنشاء جدول من 7 أعمدة ينتج ملف DOCX حقيقيًا.
- [ ] التحقق من ZIP/OOXML ووجود جدول 7 أعمدة ومحتوى الخلايا والتنسيق المطلوب.
- [ ] المعاينة والتنزيل يعملان على iOS وسطح المكتب.

### Excel / طلب الساعة
- [ ] طلب ساعة/Clock على سطح المكتب يُفهم كطلب واجهة/تطبيق، لا يُحوّل تلقائيًا إلى PDF أو XLSX.
- [ ] طلب XLSX صريح ينشئ ملف Excel حقيقيًا مع أوراق وصيغ حسب الطلب.
- [ ] لا يُستنتج نوع الملف من محادثة قديمة عند اختلاف أحدث رسالة.

### PowerPoint
- [ ] طلب عرض عربي من 8 شرائح ينتج PPTX حقيقيًا من 8 شرائح.
- [ ] التحقق من OOXML وعدد الشرائح والنصوص واتجاه العربية.
- [ ] معاينة الشرائح والتنزيل يعملان على iOS وسطح المكتب.

### نية الشات
- [ ] «كيفك» والتحيات والأسئلة العادية لا تنشئ مشروعًا أو ملفًا ولا ترث تكليفًا سابقًا.
- [ ] طلب مشروع/ملف صريح يبدأ المسار المناسب فقط.

## 3. ربط مهارات الوكيل بالأدوات

- [ ] frontend-design تُستدعى عند تغيير/إنشاء واجهة فقط، مع احترام التصميم الحالي.
- [ ] webapp-testing تُستخدم لتشغيل اختبارات المتصفح ولقطات الشاشة على بيئة معاينة فعلية.
- [ ] vercel-react-best-practices تُستخدم في مراجعة React/Next ذات الصلة.
- [ ] supabase-postgres-best-practices تُستخدم في تغييرات SQL/RLS/الفهارس.
- [ ] Superpowers متاح في بيئة Claude Code بعد التثبيت المحلي؛ لا يُدّعى أنه مثبت داخل ChatGPT.
- [ ] يظل تنفيذ الأدوات الخارجية خاضعًا للموافقة الصريحة المناسبة.

## 4. حواجز عدم الانحدار

- [ ] لا تغييرات على حركة الشات أو التمرير أو composer أو طريقة الإرسال.
- [ ] لا تعاد الخريطة؛ قرار حذفها نهائي.
- [ ] لا بيانات تجريبية تُعرض كأنها حقيقية.
- [ ] لا مفاتيح أو أسرار في المستودع أو السجلات.
- [ ] لا خدمات مدفوعة دون موافقة المستخدم.

## تقرير كل اختبار

لكل حالة سجّل: البيئة والجهاز، خطوات الضغط، الطلب/الاستجابة (مع حجب الأسرار)، حالة قاعدة البيانات قبل/بعد، النتيجة الفعلية، الدليل، وهل الاختبار آلي أم يدوي.
